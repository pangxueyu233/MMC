# Public Analysis Plan

## Scope

This public package documents the final analysis path used for figures and tables. It is intentionally narrower than the internal exploratory notebooks. The goal is to make the final workflow auditable without exposing controlled participant-level data or creating ambiguity around exploratory analyses.

## Cohort Definition

The public workflow uses metadata columns to define cohorts. It does not hard-code patient or sample identifiers.

Main analysis:

- Include only records marked by the controlled metadata as eligible for the final analysis cohort.
- Restrict treatment groups to `Nystatin` and `Fluconazole`.
- Use study time points `W0`, `W1`, `W2`, `W4`, and `W8` unless a figure explicitly states a smaller time window.
- Exclude non-primary treatment arms from the main two-arm comparisons. These samples may be described in the manuscript or controlled metadata but are not mixed into the primary two-arm analysis.
- Define any extended cohort through a metadata field such as `cohort_phase`, not by patient ID.

Every filtering step should report:

- number of participants,
- number of samples,
- counts by treatment,
- counts by diagnosis,
- counts by time point.

## Primary Statistical Approach

Primary association analyses should use standard, easy-to-review methods:

- Spearman correlation for monotonic feature-feature associations.
- Linear models or mixed models for longitudinal clinical and omics outcomes, as appropriate for the figure.
- BH/FDR adjustment across the stated family of tests.
- Explicit reporting of sample size for each analysis.

## Exploratory Analyses

Exploratory scans, nonlinear association metrics, alternative feature filters, and visual sensitivity checks should not be mixed into the public primary workflow. If included later, they should be placed in a separate `exploratory/` directory with clear labels and should not be used as the sole support for primary manuscript claims.

Nonlinear association metrics are therefore not included in this minimal public workflow. This avoids the appearance that alternative tests were used to search selectively for favorable associations.

## Figure Generation

Figures should be generated by script from derived analysis tables. No manual panel editing is part of the public workflow.

When boxplots use `outlier.shape = NA`, raw points or subject-level trajectories should remain visible elsewhere in the same panel, or the code should state that the option only prevents duplicate rendering of the same observations.

## Privacy Boundary

Public scripts must not print individual participant rows or reveal hard-coded patient/sample IDs. Individual-level QC tables should remain inside the controlled workspace.
